# Business Flow: RateBook (ทำรายการสินเชื่อ)

Source: `image_figma/MainPage.png`, `image_figma/RateBookPage.png`

Entry point: Home (`/`) → "Ratebook" quick-action card → `/ratebook`. Also reached via `/customer-lead-list` → "ทำรายการสินเชื่อ" (a row) or "จัดสินเชื่อ" (the focused lead), both of which first create a `customer_lead_opportunity` row, then land on `/ratebook?opportunityId=<id>` (see [customer-lead-list.md](customer-lead-list.md)).

## Out of scope for this phase (flagged, not silently built)

- "ข้อมูลหลักประกัน" (collateral info) "เพิ่ม/แก้ไข" button — visual only; no modal content was specified for it (unlike ข้อมูลลูกค้า).
- "บันทึก Lead" only persists to `customer_lead_opportunity` (step 8) — there's still no navigation/destination or success feedback after clicking it.
- The NCB เกรด shown, when present, is a random pick made when the underlying `customer_lead` row is created (`src/lib/actions/customer-lead.ts`), simulating a separate eNCB check — not a real eNCB API integration; it's copied onto the opportunity as part of its snapshot at creation time, never re-derived afterward.
- `CarInfoForm`'s "สแกนเล่มทะเบียน" (scan registration book) button — visual only, no OCR/scanning integration.
- `CarInfoForm`'s dropdown option lists (brand, model, sub-model, year, condition, doors, car type, engine cc, transmission, body type) are mock data in `src/lib/mock.ts`, not sourced from any real vehicle database. ยี่ห้อรถ → รุ่นรถ → รุ่นย่อย do cascade, and the catalog plus ประเภทรถ/ประเภทตัวถัง/ขนาดเครื่องยนต์ vary by the selected หลักประกัน type (มอเตอร์ไซค์/เก๋ง กระบะ ตู้/บรรทุก) — but ที่ดิน (land) has no dedicated vehicle catalog and silently falls back to the เก๋ง กระบะ ตู้ one (`toVehicleCollateralType` in `src/lib/mock.ts`), unchanged from before this pass; a real land-specific field set (title deed type, area, location, etc.) is still out of scope.
- `ProductGuide` (shown after "ดูราคาประเมิน") now computes its numbers from `getProductGuideData` (`src/lib/mock.ts`) using each vehicle model's mock `basePrice`, รุ่นปี ค.ศ.-based depreciation, and a สภาพรถ multiplier — but `basePrice` per model is still an approximate placeholder figure (not sourced from a real pricing feed/database), and รุ่นย่อย/ประเภทรถ/other fields still have no effect on the number. The component's props (`ProductGuideData`) remain shaped so a real pricing source can be swapped in later without changing the component.
- `ProductCatalog` (shown alongside `ProductGuide`) now varies by หลักประกัน, ยี่ห้อรถ, and ราคาประเมิน (step 6f), but the product rules themselves are still mock: the LTV/rate bands, the brand tiers, and the `minAppraisalPrice` thresholds in `src/lib/mock.ts` are hand-authored placeholders sized against published Thai จำนำทะเบียน figures (≈24%/ปี effective ceiling; motorcycles highest, cars/trucks lower) — not a real product master or matching engine.
