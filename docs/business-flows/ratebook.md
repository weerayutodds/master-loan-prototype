# Business Flow: RateBook (ทำรายการสินเชื่อ)

Source: `image_figma/MainPage.png`, `image_figma/RateBookPage.png`

Entry point: Home (`/`) → "Ratebook" quick-action card → `/ratebook`. Also reached via `/customer-lead-list` → "ทำรายการสินเชื่อ" (a row) or "จัดสินเชื่อ" (the focused lead), both of which first create a `customer_lead_opportunity` row, then land on `/ratebook?opportunityId=<id>` (see [customer-lead-list.md](customer-lead-list.md)).

## Flow

| # | Trigger | Result | Notes |
|---|---------|--------|-------|
| 1 | Start | User lands on Home (`/`) | Sidebar + dashboard with Quick Actions & Shortcuts |
| 2 | Click "Ratebook" quick-action card | Navigates to `/ratebook` | `href="/ratebook"`, defined in `src/lib/mock.ts` (`quickActions`) |
| 3 | `/ratebook` page loads (no `opportunityId`) | Page title "ทำรายการสินเชื่อ" renders with two panels | Loan purpose defaults to "ต้องการเงิน" (pre-selected); customer info, เลขบัตรประชาชน, NCB เกรด, collateral fields all empty (เลขบัตรประชาชน and NCB เกรด show as a neutral "-" badge, not an input); "บันทึก Lead" is always clickable but is a silent no-op with no `opportunityId` to save against — no DB reads or writes happen on this path regardless of what's clicked |
| 3b | `/ratebook?opportunityId=<id>` page loads | Sidebar is pre-filled from the `customer_lead_opportunity` row's snapshot columns; loan-question/car-info sections resume from whatever was already saved | `getCustomerLeadOpportunityById` (`src/lib/customer-lead-opportunity.ts`, Server Component read) — populates ข้อมูลลูกค้า (name + phone), a masked read-only เลขบัตรประชาชน badge, and the NCB เกรด badge from the opportunity's own snapshot (not a live join to `customer_lead`); the NCB เกรด badge only shows a grade when the snapshot's `verification_method` is `"card"` — a lead from manual entry still shows the neutral "-" badge |
| 4 | Click "เพิ่ม/แก้ไข" on ข้อมูลลูกค้า (customer info) | Customer Info modal opens | `CustomerInfoModal` — ชื่อ / นามสกุล / เบอร์โทรศัพท์ fields; lets the user override the name/phone that came from the opportunity's snapshot, if any |
| 5a | Fill name/phone → click "บันทึก" | Modal closes; left panel shows saved name + phone plus a progress badge (`filled sections / 4`) | Progress counts: customer info, เลขบัตรประชาชน, เลขทะเบียน/เลขตัวถัง, ยี่ห้อ/รุ่น. This only updates local state — nothing is written to the DB yet; see step 8 |
| 5b | Click "ยกเลิก", the backdrop, or `Esc` | Modal closes; no changes saved | |
| 6 | Click any option card (loan purpose / collateral type / refinance status) | That card becomes selected within its group (single-select per group, independent groups) | `LoanQuestionsPanel` — selections are lifted up and owned by `RatebookForm` |
| 6b | All three groups have a selection (loan purpose + collateral type + refinance status) | `LoanQuestionsPanel` is replaced by `CarInfoForm` ("กรอกข้อมูลรถ") in the right column | `RatebookForm` — this is a one-way reveal; there's no way back to `LoanQuestionsPanel` from the UI once all three are answered (the three choices remain visible as tags on the left sidebar). **Persists**: at this exact moment, `updateOpportunityLoanQuestions` writes `loan_purpose`/`collateral_type`/`refinance_status` onto the opportunity row (once, since there's no way to re-trigger it) |
| 6c | `CarInfoForm` renders | 10 dropdown fields (ยี่ห้อรถ, รุ่นรถ, รุ่นปี ค.ศ., สภาพรถ, จำนวนประตู, ประเภทรถ, ขนาดเครื่องยนต์, ระบบเกียร์, ประเภทตัวถัง, รุ่นย่อย), each backed by a mock option list in `src/lib/mock.ts`, pre-filled from the opportunity's `car_*` columns if any were already saved; a "สแกนเล่มทะเบียน" button top-right; "ดูราคาประเมิน" disabled until complete | Source: `image_figma/RateBook/CarInfo/CarInfoForm.png` |
| 6d | Fill dropdowns (any subset, in any order) | `carInfo` state updates | `carInfo` now lives in `RatebookForm` (lifted up from `CarInfoForm`) and is shared with the sidebar panel so "บันทึก Lead" (step 8) can save it too |
| 6e | Fill every dropdown except ขนาดเครื่องยนต์ (labeled "ไม่บังคับ" — optional), then click "ดูราคาประเมิน" | Button becomes enabled once complete; clicking it persists the filled-in car info | **Persists**: `updateOpportunityCarInfo` writes all `car_*` columns onto the opportunity row. There is still no appraisal-price destination or calculation — only the DB write is new |
| 7 | Click "Dipchip" next to เลขบัตรประชาชน | Navigates to `/customer-form` (ตรวจสอบข้อมูลลูกค้า) | Plain navigation; completing that flow and clicking "ดำเนินการต่อ" there creates/updates a `customer_lead` row and redirects to `/customer-lead-list?leadId=<id>` (see [customer-form.md](customer-form.md)); from there, clicking "ทำรายการสินเชื่อ" on that lead's row creates a fresh opportunity and returns here as `/ratebook?opportunityId=<new id>` (see [customer-lead-list.md](customer-lead-list.md)). The button only shows when the opportunity's snapshot `verification_method` isn't already `"card"` |
| 8 | Click "บันทึก Lead" | No navigation/destination — button stays on the page | Always clickable, regardless of how much of the form is filled in. **Persists**: `updateOpportunityCustomerInfo` (customer name/phone, if the modal has been saved at least once), `updateOpportunityCollateralDetail` (เลขทะเบียน/เลขตัวถัง + ยี่ห้อ/รุ่น), and `updateOpportunityCarInfo` (whatever `carInfo` currently holds, complete or not) all fire on this click (`src/lib/actions/customer-lead-opportunity.ts`), overwriting this opportunity's row in one go. The underlying `customer_lead` row is never touched. This is the single commit point for the whole opportunity — the customer-info and collateral-detail modals, the ยี่ห้อ/รุ่น "เพิ่ม" button, and `CarInfoForm`'s own dropdowns only update local/lifted state and no longer persist on their own (except "ดูราคาประเมิน", step 6e, which still separately persists car info once complete) |

## Out of scope for this phase (flagged, not silently built)
- "ข้อมูลหลักประกัน" (collateral info) "เพิ่ม/แก้ไข" button — visual only; no modal content was specified for it (unlike ข้อมูลลูกค้า).
- "บันทึก Lead" only persists to `customer_lead_opportunity` (step 8) — there's still no navigation/destination or success feedback after clicking it.
- The NCB เกรด shown, when present, is a random pick made when the underlying `customer_lead` row is created (`src/lib/actions/customer-lead.ts`), simulating a separate eNCB check — not a real eNCB API integration; it's copied onto the opportunity as part of its snapshot at creation time, never re-derived afterward.
- `CarInfoForm`'s "สแกนเล่มทะเบียน" (scan registration book) button — visual only, no OCR/scanning integration.
- `CarInfoForm`'s dropdown option lists (brand, model, year, condition, doors, car type, engine cc, transmission, body type, sub-model) are mock data in `src/lib/mock.ts`, not sourced from any real vehicle database; ยี่ห้อรถ/รุ่นรถ are not cascading (picking a brand doesn't filter the model list).
- What happens after "ดูราคาประเมิน" is clicked — no appraisal-price destination or calculation exists yet; only the underlying `customer_lead_opportunity` row gets the car info written to it.
- `/ratebook?leadId=<id>` (bare lead, no opportunity) is no longer a supported route shape — every real entry point now creates an opportunity first (see [customer-lead-list.md](customer-lead-list.md)); hand-typing a `leadId` param is silently ignored, behaving exactly like the no-param case (step 3).
- The ยี่ห้อ/รุ่น "เพิ่ม" button and the collateral-detail modal's own "บันทึก" only update local state — they don't persist by themselves; only clicking "บันทึก Lead" writes them to the DB (step 8). There's still no dedicated "collateral info" modal beyond what `CollateralDetailModal` already covers.
